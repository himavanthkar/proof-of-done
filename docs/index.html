Proof of Done

AI coding agents often say “done” when the work is wrong. Proof of Done is a team of AI agents that has to show evidence before it can say done. When it can't, it asks you one question instead of guessing.

The problem

Short goals hide decisions

Give an AI agent a one-line goal and it has to fill in everything the goal doesn't say. A normal agent makes those choices silently, writes code, and reports “done”. You only find out later that it guessed differently than you would have.

Proof of Done writes every one of those choices down as an assumption, turns each into a test, and locks the tests before any code exists. Then it has to prove the code passes them.

Think of it as the difference between a student grading their own homework and a teacher who writes the answer key before the student starts.

Example goal
Return the business-day count between two ISO dates (YYYY-MM-DD), excluding weekends

Questions this goal leaves open:

  • Are the start and end dates both counted?
  • What if the start date is after the end date?
  • Does Feb 29 count in a leap year?

    How it works

    Six steps, one strict rule

    1. Write the contract

      A spec agent lists its assumptions and writes tests for them. The tests get a SHA-256 fingerprint so nobody can quietly edit them.

    2. Build

      A builder agent writes the code. It can read the tests but can't change them.

    3. Run it safely

      Tests run in a sandbox with no network and no API keys, here an NVIDIA OpenShell micro-VM.

    4. Attack the tests

      Mutation testing breaks the code on purpose. If the tests don't catch the broken versions, they get strengthened.

    5. Get a second opinion

      NVIDIA Nemotron audits everything and can say a test itself is wrong.

    6. Decide with plain code

      No AI makes the final call. If any check fails, it retries, re-plans, fixes the disputed test, or asks you one question.

    It may only say done when all three are true: tests pass · at least 80% of broken versions caught · verifier approves Every run ends with a receipt: assumptions, test fingerprints, results, the verifier's verdict, and the cost.
    Real-world use cases

    Where a wrong “done” costs real money

    The demo counts business days on purpose: in real systems, getting a day count wrong changes what someone is paid. The same pattern applies anywhere an AI's “done” gets trusted without checking.

    Payroll and loan interest

    Day counts decide money. One assumption about whether the end date counts changes what people are paid or charged.

    AI pull requests

    Coding agents open pull requests that say “fixed”. A receipt shows reviewers the locked tests and the evidence, so they can trust the claim.

    Finance and tax rules

    Rounding, thresholds and cutoff dates are full of edge cases. Writing each assumption down catches the expensive ones before they ship.

    Healthcare calculators

    For dose and unit conversions, “Which unit did you mean?” is far safer than a confident guess.

    Data pipelines

    When an agent cleans or transforms data, locked tests prove the output follows the rules before anyone builds on it.

    Agents nobody is watching

    Agents that run overnight or in the background have no human checking their work. There, “done” has to mean done.

    What didn't work

    Our honest findings

    • The different-family verifier didn't measurably help. Using the builder's own model family as the verifier scored about the same (19.5% vs 21.0% false “done”). The gains come from locked tests, mutation testing and the strict rule.
    • The verifier's confidence says little. 80% of its approvals were right: 82% at confidence 100 and 76% at 95–99.
    • It sometimes makes things worse. On 5 tasks the solo agent was right but Proof of Done locked a different assumption.
    • The sample is small. With 100 tasks the confidence intervals overlap, so the gap with the self-checking agent isn't statistically significant yet.
    • We tuned on separate tasks. Prompt fixes were made on tasks 1–100; every number on this page comes from tasks 101–200.
    The takeaway

    Done means done.
    No receipt, no done.

    “Done” should be a claim with evidence attached. When the evidence can't be produced, the right answer is one good question, not a confident guess.
